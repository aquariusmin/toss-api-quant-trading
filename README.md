# tqt — 토스증권 Open API 퀀트 트레이딩 봇

국내(KRX)·미국 주식을 **백테스트 → 페이퍼 트레이딩 → 실거래** 순서로 자동매매하는 봇입니다.
텔레그램·디스코드 알림과 웹 대시보드가 붙어 있어, 라즈베리파이에 올려두고
휴대폰으로 확인·정지할 수 있습니다.

```
전략(논문 기반)  →  리스크 한도  →  브로커(paper | live)  →  토스 Open API
       ↓                 ↓                  ↓
   백테스트 검증      킬 스위치        텔레그램 + 대시보드
```

---

## 먼저 솔직하게 — "아무것도 안 하고 돈 벌기"에 대해

목표를 그렇게 잡으셨으니, 이 코드가 실제로 무엇을 해줄 수 있고 무엇은 못 하는지
분명히 적어두겠습니다.

**이 봇이 해주는 일**: 검증된 규칙을 사람 손 대지 않고, 감정 없이, 비용을 정확히
계산하면서, 리스크 한도를 어기지 않고 매달 실행합니다. 자동화가 실제로 이기는 지점은
"더 좋은 예측"이 아니라 **일관성**입니다. 사람은 하락장에서 규칙을 어깁니다. 봇은 안 어깁니다.

**이 봇이 해줄 수 없는 일**: 수익 보장. 아래 백테스트에서 가장 좋은 전략도
2022년에는 손실이었고, 최대 낙폭은 -14%였습니다. 시드 100만원이면 잘 되는 해에
연 5~10만원 수준입니다. **자동매매가 돈을 버는 이유는 매매가 자동이기 때문이 아니라,
자동화한 규칙에 우위(edge)가 있기 때문입니다.** 우위 없는 전략을 자동화하면
손실을 자동화하게 됩니다.

**그래서 이 프로젝트가 택한 입장**: 제가 새로 발명한 전략은 하나도 없습니다.
전부 10년 이상 공개되어 검증된 논문·서적의 규칙이고(→ [참고 문헌](#참고-문헌)),
비용은 추측이 아니라 **이 계좌의 실제 수수료율을 API에서 읽어와** 계산하며,
성과는 인샘플이 아니라 **walk-forward 아웃오브샘플**로 보고합니다.
낙폭을 줄이는 데 코드의 상당 부분이 들어가 있습니다. 수익률보다 **살아남는 것**이
먼저이기 때문입니다.

**세 단계를 건너뛰지 마세요.** 백테스트 → 페이퍼(최소 1개월) → 소액 실거래 순서입니다.

## 1. 빠른 시작

```bash
git clone https://github.com/aquariusmin/toss-api-quant-trading
cd toss-api-quant-trading

python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

cp .env.example .env      # 값 채우기 (아래 참고)
tqt doctor                # 설정 점검 — 여기서 전부 OK가 나와야 합니다
tqt data sync             # 시세 16년치 내려받기 (약 1분)
tqt backtest run --sleeve kr-global-etf --all
```

### `.env` 채우기

| 키 | 얻는 곳 |
|---|---|
| `toss_client_id`, `toss_client_secret` | 토스증권 WTS → 설정 → Open API |
| `toss_bank_account` | 종합매매 계좌번호 (숫자만) |
| `TELEGRAM_BOT_TOKEN` | 텔레그램 `@BotFather` 에서 봇 생성 |
| `TELEGRAM_CHAT_ID` | 봇에 아무 말이나 보낸 뒤 `https://api.telegram.org/bot<TOKEN>/getUpdates` |
| `DISCORD_WEBHOOK_URL` | 서버 설정 → 연동 → 웹후크 |
| `TQT_DASHBOARD_TOKEN` | `openssl rand -hex 24` 로 생성 |

> **허용 IP 등록이 필수입니다.** 토스는 등록되지 않은 IP에서의 호출을 403으로 막습니다.
> 설정 → Open API → 허용 IP 관리에 **봇이 돌아가는 서버의 공인 IP**를 넣으세요.
> 가정용 인터넷은 IP가 바뀌므로, 봇이 30분마다 확인해서 바뀌면 텔레그램으로 알려줍니다
> (`tqt doctor` 에서도 확인 가능).

## 2. 3단계 로드맵

### 1단계 — 백테스트 (지금 바로)

```bash
tqt data sync                                              # 시세 수집
tqt backtest run --sleeve kr-global-etf --all               # 전략 비교
tqt backtest walkforward --sleeve kr-global-etf --strategy faber   # ★ 아웃오브샘플
tqt backtest sweep --param sma_days --values 100,150,200,250,300  # 파라미터 민감도
tqt backtest plan                                          # 포트폴리오 전체
```

**다음 단계로 넘어가는 조건**: walk-forward 아웃오브샘플에서 최대낙폭이 내가 견딜 수
있는 수준이고, `decay` 비율이 1.0 근처일 때. decay가 0.5 이하면 과최적화입니다.

### 2단계 — 페이퍼 트레이딩 (최소 1개월)

`.env` 에 `TQT_MODE=paper` (기본값).

```bash
tqt paper reset --cash 1000000     # 가상 100만원으로 시작
tqt cycle --force                  # 지금 즉시 한 번 돌려보기
tqt run --dashboard                # 스케줄러 + 대시보드 상시 실행
```

페이퍼는 **실제 토스 호가창에 체결**시킵니다. 매수는 실제 최우선 매도호가를,
매도는 최우선 매수호가를 치므로 스프레드 비용이 그대로 반영됩니다.
수수료·세금·환전 비용도 실계좌와 같은 요율입니다.

**다음 단계로 넘어가는 조건**: 한 달 이상 무중단 실행, 리밸런싱이 최소 1회 정상 수행,
텔레그램 알림 정상, 원장(주문·체결)이 예상과 일치.

### 3단계 — 실거래 (소액부터)

```bash
# .env 에 두 줄이 모두 있어야 합니다 — 오타로 실거래가 켜지는 것을 막기 위한 장치
TQT_MODE=live
TQT_LIVE_CONFIRM=I_UNDERSTAND_REAL_MONEY
```

```bash
tqt doctor          # 반드시 전부 OK
tqt status          # 계좌 확인
tqt run --dashboard
```

→ 넘어가기 전에 [실거래 체크리스트](#실거래-체크리스트)를 확인하세요.

## 3. 실측 백테스트 결과

국내 상장 글로벌 ETF 8종 + 국고채 2종, 2011-01 ~ 2026-08, 시드 100만원.
**토스 실제 수수료(국내 0.015%) · 슬리피지 10bp · 원 단위 정수 주식 · 다음날 시가 체결** 반영.

| 전략 | CAGR | 변동성 | Sharpe | 최대낙폭 | Calmar | 연 회전율 | 비용/원금 |
|---|---|---|---|---|---|---|---|
| 매수보유 (벤치마크) | 8.94% | 11.2% | 0.84 | **-20.1%** | 0.44 | 0.25회 | 0.1% |
| **Faber 이동평균** | 5.73% | **6.5%** | **0.92** | **-14.5%** | 0.40 | 2.98회 | 1.0% |
| 듀얼 모멘텀 | 7.60% | 16.9% | 0.53 | -30.5% | 0.25 | 4.70회 | 1.7% |
| VAA | 10.61% | 18.3% | 0.66 | -40.6% | 0.26 | 10.0회 | 4.2% |

### Walk-forward 아웃오브샘플 (5년 학습 / 2년 검증)

| 전략 | 인샘플 CAGR | **OOS CAGR** | OOS Sharpe | OOS 최대낙폭 | decay |
|---|---|---|---|---|---|
| Faber | 5.73% | **7.36%** | 1.01 | -14.1% | ×1.28 |
| 듀얼 모멘텀 | 7.60% | 7.57% | 0.49 | -30.5% | ×1.00 |
| 매수보유 | 8.94% | 11.10% | 0.97 | -20.1% | ×1.24 |

decay가 모두 1.0 이상 → **과최적화 흔적이 없습니다.** 당연한 결과이기도 합니다.
이 전략들은 제가 이 데이터에 맞춰 튜닝한 파라미터가 없습니다.

### 이 숫자에서 읽어야 할 것

1. **매수보유가 CAGR로는 이깁니다.** 전술적 배분(Faber)은 수익률을 **낙폭과 교환**합니다.
   -14% vs -20%가 -3%p의 CAGR 값을 하는지는 본인 성향의 문제입니다.
   소액 검증 단계에서는 "계속 켜둘 수 있는" 쪽이 중요하다고 판단해 Faber에 비중을 더 줬습니다.
2. **2022년에는 전부 손실이었습니다.** Faber -2.7%, 듀얼모멘텀 -9.7%. 주식과 장기채가
   동시에 빠지면 숨을 곳이 없습니다. 이런 해가 또 옵니다.
3. **VAA는 CAGR이 가장 높지만 낙폭 -40%, 회전율 10회입니다.** 원금의 4.2%를
   비용으로 씁니다. 그래서 기본 배분에서 뺐습니다.
4. **미국 상장 ETF를 자주 거래하면 안 됩니다.** 같은 전략을 미국 슬리브에 적용하면
   비용이 원금의 16~43%까지 갑니다 (수수료 0.1% + 환전 0.1%). 그래서 기본 배분은
   자주 거래하는 전략을 **국내 상장** ETF(S&P500·나스닥100 포함)에만 씁니다.

> 주의: 유니버스가 "오늘 존재하는 ETF"로 구성되어 있어 생존 편향이 약간 있습니다.
> 상장폐지된 ETF는 포함되지 않았습니다. 대형 지수 ETF라 영향은 작지만 0은 아닙니다.

## 4. 기본 포트폴리오

`config/portfolio.toml` 에서 고칩니다. 기본값:

| 비중 | 슬리브 | 전략 | 왜 |
|---|---|---|---|
| 50% | 국내상장 글로벌 ETF | Faber 이동평균 | 낙폭 최소, Sharpe 최고 |
| 25% | 국내상장 글로벌 ETF | 듀얼 모멘텀 | Faber와 신호가 달라 분산 효과 |
| 25% | 미국상장 ETF | 매수보유 | 회전율 0.12회 → 비싼 미국 수수료 영향 없음 |

전략을 여러 개 병행하는 이유: 한 전략이 부진할 때 다른 전략이 받쳐줘서 합산
곡선이 더 매끄러워집니다. 하나가 조용히 망가져도 계좌 전체가 날아가지 않습니다.

## 6. 명령어

```bash
# 진단 · 계좌
tqt doctor                 # 실행 전 점검 (제일 먼저 쓸 명령)
tqt accounts               # 계좌 목록, accountSeq 확인
tqt costs                  # 내 계좌 실제 수수료율
tqt status                 # 평가금액·보유·손익 요약

# 데이터
tqt data sync              # 시세 수집/갱신
tqt data status            # 보유 데이터 현황

# 백테스트
tqt backtest run --sleeve kr-global-etf --all
tqt backtest walkforward --strategy faber
tqt backtest sweep --param sma_days --values 100,150,200,250,300
tqt backtest plan

# 페이퍼 · 실행
tqt paper reset --cash 1000000
tqt cycle --force          # 한 번만 실행 (테스트용)
tqt run --dashboard        # 상시 실행
tqt dashboard              # 대시보드만

# 제어
tqt halt "이유"  /  tqt resume
tqt notify-test
```

### 텔레그램 명령어

`/status` `/positions` `/report` `/orders` `/signals` `/plan` `/rebalance`
`/halt` `/resume` `/ip` `/help`

명령은 `TELEGRAM_CHAT_ID` 로 등록된 채팅에서만 동작합니다(그 외는 무시).

## 7. 라즈베리파이 배포

**Docker (64-bit 라즈베리파이 OS 권장)**

```bash
cp .env.example .env && vi .env
docker compose up -d
docker compose logs -f
docker compose exec bot tqt doctor
```

**systemd (Docker 없이)**

`deploy/tqt.service` 상단 주석에 설치 순서가 있습니다.
`deploy/tqt-sync.timer` 는 매일 16:30 KST에 시세를 갱신합니다.

> 대시보드를 인터넷에 직접 열지 마세요. 집 안 네트워크나 Tailscale/WireGuard
> 같은 VPN 안에서만 접근하는 것을 권합니다. 계좌 잔고와 킬 스위치가 노출됩니다.

### 스케줄

| 시각(KST) | 작업 |
|---|---|
| 15:00 월~금 | 국내 리밸런싱 판단 (정규장 중, 종가 단일가 전) |
| 04:30 화~토 | 미국 리밸런싱 판단 (미국 정규장 마감 30분 전) |
| 08:00 매일 | 일일 리포트 발송 |
| 30분마다 | 공인 IP 확인 + 평가금액 기록 |

실제 리밸런싱은 **월말 마지막 영업일**에만 일어납니다. 그 판단은 날짜 계산이 아니라
**토스 장운영 캘린더**에서 "다음 영업일이 다른 달인가"로 판정하므로,
대체공휴일(예: 2026-08-17 광복절 대체휴일)도 자동 처리됩니다.

## 8. 토스 Open API 제약사항 (직접 측정한 값)

이 프로젝트를 만들면서 실제로 확인한 내용입니다. 설계에 직접 영향을 줬습니다.

| 항목 | 실측 |
|---|---|
| 모의투자/샌드박스 | **없음** → 페이퍼 트레이딩을 직접 구현해야 함 |
| WebSocket | **없음** → REST 폴링만 가능 |
| 캔들 간격 | `1d`, `1m` **뿐** |
| 일봉 히스토리 | 2010년까지 (16년 이상) — 백테스트 충분 |
| **1분봉 히스토리** | **약 4일치뿐** → **인트라데이 백테스트 불가** |
| 캔들 페이지 | 1회 최대 200봉, **최신순** 정렬, `nextBefore` 커서 |
| 액세스 토큰 | 24시간 (`expires_in=86399`) |
| 허용 IP | 필수. 미등록 IP는 403 `edge-blocked` |
| 계좌 종류 | 종합매매(BROKERAGE)만. **연금계좌 자동매매 불가** |
| 숫자 표현 | 전부 문자열 → `Decimal` 사용 필수 (이 코드는 float를 쓰지 않습니다) |
| Rate limit | 그룹별 초당 제한. `ACCOUNT` 1회/초가 가장 타이트 |

**1분봉이 4일치뿐이라는 점이 중요합니다.** 단기·데이트레이딩 전략은 이 API로는
백테스트 자체가 불가능합니다. 저빈도 일봉 전략을 택한 것은 취향이 아니라 제약입니다.

```
├── portfolio.py         멀티 전략 배분
├── risk.py              리스크 한도 · 킬 스위치
├── runner.py            트레이딩 루프 · 스케줄러 · 텔레그램 명령
├── ops.py               장운영 캘린더 · IP 감시 · 사전점검
├── tick.py              KRX 호가단위
├── cli.py               tqt 명령
├── toss/                API 클라이언트 (인증·레이트리밋·재시도·에러·모델)
├── data/                SQLite 저장소 · 시세 수집
├── strategy/            전략 (논문 기반)
├── backtest/            엔진 · 비용모델 · 지표 · walk-forward
├── execution/           브로커 (paper / live)
├── notify/              텔레그램 · 디스코드
└── web/                 FastAPI 대시보드
```

설계상 중요한 점 두 가지:

- **전략은 목표 비중만 반환합니다.** 주문 생성·현금 관리·리스크 검사는 별도 계층입니다.
  덕분에 **똑같은 전략 객체가 백테스트·페이퍼·실거래를 모두 구동**합니다.
  페이퍼와 실거래가 서로 다른 코드를 쓰면 페이퍼 단계가 무의미해집니다.
- **백테스트는 종가에 판단하고 다음날 시가에 체결합니다.** 미래 데이터를 볼 수 없도록
  전략에 넘기는 데이터프레임을 판단일까지 잘라서 전달합니다.
  룩어헤드 편향이 "조심해서 피하는" 것이 아니라 **구조적으로 불가능**합니다
  (테스트로 검증: `tests/test_engine.py`).

```bash
pytest          # 101개 테스트
ruff check src/
```

## 참고 문헌

전략은 모두 아래 문헌의 규칙을 그대로 구현한 것입니다.

- **Gary Antonacci**, *Dual Momentum Investing* (2014) — 상대 + 절대 모멘텀.
  절대 모멘텀 필터가 2008년식 폭락에서 살아남게 하는 부분입니다.
- **Mebane Faber**, *A Quantitative Approach to Tactical Asset Allocation* (2007) —
  10개월 이동평균 추세 필터. 아웃오브샘플에서 가장 잘 버틴 단순 규칙.
- **Wouter Keller & Jan Willem Keuning**, *Vigilant Asset Allocation* (2017) —
  13612W 모멘텀과 breadth 방어. 유니버스 크기에 따라 B값을 조정해야 합니다.
- **Ernest Chan**, *Quantitative Trading* — 백테스트 함정(룩어헤드·생존편향·데이터스누핑).
- **David Bailey & Marcos López de Prado**, *The Deflated Sharpe Ratio* (2014) —
  파라미터를 여러 개 시험했을 때의 Sharpe 보정. `tqt backtest sweep` 의 `DeflSharpe`.
- **Andreas Clenow**, *Stocks on the Move* (2015) — 변동성 기반 포지션 사이징.
- **Robert Carver**, *Systematic Trading* — 리스크 목표 기반 설계, 과최적화 회피.
